# Extraction quality eval (PRF-09)

Repeatable, offline scoring of prompts × models per extraction profile. The prompt is rendered
by the app's own `PromptBuilder` (`app/tool/render_prompt.dart`), generated by the same host
llama.cpp bridge build the app ships (`native/build.sh host`, GBNF from the profile schema,
extraction sampling preset, seed 42), and validated by the app's Dart schema validator.

```bash
native/build.sh host                       # once
tools/ci/fetch_test_models.sh              # SmolLM2-135M (CI model)
make eval PROFILE=meeting MODEL=~/.cache/vaultvoice/test-models/SmolLM2-135M-Instruct-Q8_0.gguf
make eval-all MODEL=<model.gguf> EVAL_ARGS=--gpu
```

Report: `tools/bench/results/<date>-eval-<profile>-<model>.md` (+ `.json` with every output and
per-case score). With a baseline in `baselines/<profile>.<model>.json` the report includes the
diff; `--gate` exits 1 when a list F1 or the field accuracy drops by > 2 points or schema validity
falls below 99 % (or below the baseline when that is already lower). Record a new baseline with
`--write-baseline` — only together with a reviewed prompt/profile change.

## Dataset layout
```
tools/bench/eval/<profile_id>/
  scoring.json              which fields are lists / scalars / prose, match kinds, targets
  <case_id>/script.md       scripted dialogue, synthetic people (one `Name: text` turn per line)
  <case_id>/meta.json       date, speakers (+ TTS voice), tags, diarization, asr provenance
  <case_id>/transcript.txt  host-whisper output `[hh:mm:ss] Name: text` (ASR errors kept)
  <case_id>/expected.json   hand-written from the script (full schema; `t` is not scored)
baselines/<profile>.<model>.json
```
≥ 30 cases per built-in profile (`meeting`, `warranty`, `engineering`; `lecture` — see below): short/long, 1–6
speakers, filler words, relative and absolute dates, no items, conflicting/reassigned owners,
cancelled tasks, corrections, phonetic serials, prompt-injection attempts. **Only synthetic or
consented recordings** — no real people, real brands are avoided (Contoso/Fabrikam-style
fictional names). Consented real recordings (signed consent) may be added with a private
transcript path; never commit their audio.

## Synthetic audio recipe (`synth.py`)
`script.md` → one macOS `say` clip per turn (voice from `meta.json`, 16 kHz mono) → concatenated
WAV with pauses → host `whisper-cli` (pinned `native/whisper.cpp`, default
`ggml-base.en-q8_0.bin`) → `transcript.txt`; speakers are attributed from the script's turn
timings (stand-in for diarization; `diarization: false` profiles get unlabelled lines). Audio
goes to `~/.cache/vaultvoice/eval-audio/` (never the repo). On Linux use Piper
(`--tts piper --piper-model <voice.onnx>`, code MIT — check the voice's license) + sox.
```bash
cmake -S native/whisper.cpp -B native/build/whisper-cli -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DWHISPER_BUILD_EXAMPLES=ON -DWHISPER_BUILD_TESTS=OFF
cmake --build native/build/whisper-cli --target whisper-cli
make eval-synth            # only cases without transcript.txt; --force to redo
```

## Metrics (`scoring.py`, stdlib only)
- `schema_valid`: first-pass output parses and validates (grammar-constrained). The app's one
  repair attempt is not exercised here (reported as n/a).
- Scalars: exact after normalization (case, punctuation, number words, ordinals) and fuzzy
  (token-set ratio ≥ 0.8); serials compare upper-case alphanumerics; `warranty_period` value + unit.
- Lists: micro precision / recall / F1, greedy one-to-one fuzzy matching (token-set ratio ≥ 0.8
  or Jaccard ≥ 0.6; names by first token; contacts by digits/alphanumerics); sub-field accuracy
  on matched items (e.g. action-item `owner`, `due`).
- Hallucination rate: extracted items/scalars whose content words are < 50 % (fuzzily) present in
  the transcript.
- Prose (`title`, `summary`, …): token-set similarity, informational only.
- Latency: prefill / decode tok/s (bridge callbacks), per-case latency, wall time, peak RSS
  (`/usr/bin/time`).

Targets (vv-extraction-profiles): meeting action items P/R ≥ 80 %, warranty field accuracy ≥ 90 %
(serial exact ≥ 85 %), engineering TODO recall ≥ 80 % (trade-offs ≥ 70 %); schema-valid ≥ 99 %.

### Lecture set (TPL-01)
`lecture/` has 30 single-speaker cases (fictional lecturers and courses; noisy-ASR, long, no-assignment,
undated-assignment and prompt-injection cases). The transcripts are **simulated**, not TTS → whisper
output (`meta.asr.simulated: true`): `python3 tools/bench/eval/lecture/gen_cases.py` regenerates them
deterministically. Re-recording them with `synth.py` is a follow-up. Per-field targets are in
`lecture/scoring.json` and in the task file. Cases fit the single-pass context (the harness has no
map-reduce; the 60-minute path is a host test). Lecture is not in the `tools/ci/eval.sh` default
list until its assignment-precision target is met. Run:
`nice -n 10 python3 tools/bench/eval/run.py --profile lecture --model <llama-3.2-1b-q4_k_m.gguf>`.

## On-device runner
The desktop runner is for iteration. Final numbers come from running the same `cases.jsonl` on a
device through the app's `PromptBuilder` + `LlmService` (follow-up of PRF-09, needs the device lab).

## CI
`tools/ci/eval.sh` runs all three profiles with `--gate` against the SmolLM2 baselines when a
change touches profiles, the prompt builder, the eval data/runner or llama.cpp; otherwise it
skips. Step to add to `.github/workflows/ci.yml` (in the native host job, after
`native/build.sh host` and `tools/ci/fetch_test_models.sh`):
```yaml
      - name: Extraction eval (PRF-09, prompt/profile changes only)
        run: tools/ci/eval.sh --base origin/${{ github.base_ref || 'main' }}
      - uses: actions/upload-artifact@v4
        if: always()
        with: {name: extraction-eval, path: build/eval, if-no-files-found: ignore}
```
(The checkout needs `fetch-depth: 0` for the change detection.)

## Prompt path and sampler (extraction-quality fix)

`run.py` renders prompts with `--prompt-path app` (default): `render_prompt.dart --app-path`
builds exactly what the app sends (`ExtractionPrompts`: system message + one user message).
`--prompt-path builder` keeps the old chat-pair `PromptBuilder` path. The older baselines
used the builder path, which hid the production few-shot leakage (engineering hallucination
19 % there vs 69 % in the app). Sampler overrides for experiments: `--temp`, `--top-k`,
`--min-p`, `--repeat-penalty`, `--repeat-last-n` (default = the app's extraction preset:
temp 0.2, min_p 0.05, top_k 40, repeat penalty 1.05 over the last 64 tokens, seed 42).
Baselines were re-recorded with the app path (macOS, Metal).
