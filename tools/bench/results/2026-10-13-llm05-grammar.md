# LLM-05 grammar overhead (HOST, not a target device)

Tool: `tools/bench/llm_grammar/run.sh <model> 3 <gpu>` (`grammar_bench.c` over the real bridge:
`vv_json_schema_to_gbnf` + `vv_llm_generate_async`). Same chat-templated synthetic meeting prompt
(1291 tokens), greedy, 256 generated tokens, n = 3 per mode, median (min–max). Grammar = the
meeting schema (title, summary, ≤ 20 action items with `text`/`owner`/`t` timestamp pattern)
converted by llama.cpp's json-schema-to-grammar. Host: Apple M3 Pro, macOS 27.0.1, llama.cpp
v0.6.0 (`d812350`), 2026-10-13, load average 13–16 (other agents building).

Modes:
- **none** — unconstrained (reference speed).
- **full** — grammar sampler first in the chain: masks all 128k candidates every step (what the
  LLM-01 spike and LLM-04 initially did).
- **lazy** — sample with the plain chain, check only the chosen token against the grammar,
  full mask + resample only on rejection (llama.cpp `common/sampling.cpp` strategy). LLM-05 default.

- Lazy output is byte-identical to full-mask output under greedy decoding (ctest `vv_grammar`
  asserts it), so the constraint is unchanged — only the cost.
- Target < 20% overhead: **met on the host** with lazy mode. Device rows: `docs/test-plans/device/LLM-05.md`.
